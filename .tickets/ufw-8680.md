# Organize project navigation by capability

## Initiative Intent

The overview should act as the normal project summary and organizing document. Capability context should make related screens and flows easy to find without hiding standalone artifacts.

## Outcome

The selected overview provides capability-centered project navigation. Every valid catalog document remains discoverable, including artifacts not referenced by that overview.

## User and Operator Context

Byron should be able to scan product scope, select a capability, and open its related artifacts. The navigation must not claim stronger semantic relationships than the source provides.

## Current System and Evidence

- `DiagramCatalog` already provides path, type, title, validity, and diagnostic count.
- Overview groups and capabilities already preserve source order.
- The prior ticket adds ordered flow and wireframe screen references.
- The current overview flow shelf combines folder inventory and explicit flow links.
- Project rules state that same-folder discovery is inventory only.
- Overview source refresh keeps its last valid board when a new read fails.

## Requirements

- Build a pure navigation projection from the selected overview and `DiagramCatalog`.
- Project groups, capabilities, related flows, and related wireframe screens.
- Preserve source order for groups, capabilities, and relationships.
- Keep the selected overview visible as the workspace home item.
- Expand the selected capability to show related screens and flows.
- Provide compact `All diagrams` and `Not linked here` sections.
- Label files as `Not linked here`, not globally unlinked.
- Keep invalid files visible with diagnostics through all-diagram access.
- Let several capabilities open the same artifact with distinct origin context.
- Recompute navigation after a successful overview source refresh.
- Keep the last valid projection while the overview is stale.
- Clear only context that no longer exists after a valid refresh.
- Restore focus when navigation changes the main renderer.
- Support keyboard operation and a usable narrow-screen navigator.

## Settled Decisions

- Relationships come from the active overview and its active view.
- The catalog supplies inventory, not semantics.
- Direct file opens do not trigger a scan of every overview.
- An artifact linked from another overview can still appear as `Not linked here`.
- The overview chooser remains the fallback for several valid overviews.
- The complete diagram inventory remains the fallback without an overview.

## Constraints and Non-Goals

- Do not build or persist a project-wide relationship registry.
- Do not infer links from folders, names, content, or wireframe embeds.
- Do not add recursive folder projects or nested project navigation.
- Do not add drag-and-drop capability organization.
- Do not add coverage scores, completion status, or lifecycle tracking.
- Do not overwrite a flow browser-local working copy during overview refresh.

## Dependencies and Coordination

Depends on `ufw-w2gh`, which depends on the shared shell. The projection needs both flow and wireframe relationship shapes.

This ticket owns the capability navigator and its pure projection. It does not own final removal of all duplicate renderer chrome.

## Scope

- Add one pure active-overview navigation projection.
- Render capability-centered project navigation in the shared shell.
- Add all-diagram and `Not linked here` access.
- Keep context correct across active overview variants and source refresh.
- Add keyboard, focus, and narrow-screen behavior for this navigation.

## Known Implementation Context

- `overviewFlowInventory` already distinguishes explicit capability links from same-folder flow inventory.
- `OverviewWorkbench` already tracks active variants, selection, source refresh, and stale state.
- `Home` already receives the catalog and selected document response.
- Use active overview data. Do not create a second source of truth in the shell.

## Allowed Implementation Discretion

- Choose the smallest pure projection shape needed by the shell.
- Choose compact disclosure and narrow-screen behavior using native controls.
- Choose whether `All diagrams` is inline, a drawer, or a small secondary view.
- Reuse or replace `overviewFlowInventory` only if the new projection fully preserves its tested semantics.

## Edge Cases and Failure Behavior

- Empty overview, ungrouped capabilities, and capabilities with no relationships.
- Several capabilities reference one flow or wireframe screen.
- One capability references several screens or flows.
- Active overview variants add, remove, or change references.
- The selected capability disappears after a valid refresh.
- A failed refresh keeps the last valid projection and marks it stale.
- Invalid or wrong-type files stay available through diagnostics.
- A direct artifact URL has no invented capability backlink.
- Another overview references a file that is not linked from the active overview.

## Proof and Acceptance

- Pure tests cover empty, grouped, ungrouped, shared, several-reference, variant, invalid, and stable-order projections.
- `pnpm test:overview`, `pnpm test:dsl`, `pnpm typecheck`, and `pnpm build` pass.
- The resume overview exposes its capability groups in project navigation.
- The selected resume capability exposes its related screen and flow.
- Every valid document remains reachable through `All diagrams`.
- Files outside the active overview appear as `Not linked here` without a false global claim.
- Successful refresh updates navigation; failed refresh keeps the last valid state.
- Keyboard and narrow-screen browser checks pass.

## Rollout and Recovery

Keep the overview chooser and all-diagram inventory as a shell fallback. If capability navigation harms the canvas or becomes misleading, hide it and retain those simpler paths.

## Below the Cut Line

- Project-wide backlinks for direct opens.
- Stored relationship registry.
- Project manifest, preferred overview metadata, or nested projects.
- In-app relationship editing and automatic inference.
- Flow-node-to-screen relationships.
- Coverage and lifecycle dashboards.
